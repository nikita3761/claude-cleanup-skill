# Deep disk cleanup (macOS)

## Overview
Scan read-only first, delete only what regenerates itself and is not in use, decide everything else **with the user in batches**, and move personal files to an external drive only via **copy → checksum verify → original to Trash**, leaving a restore manifest on the drive.

**Core principle:** the user loses nothing they did not explicitly agree to lose, and anything moved can be put back from the manifest.

## Hard rules
1. **Recently used = untouchable.** User data, apps, tools, runtimes, worktrees used or modified within the last **14 days** are not deleted or moved, whatever their size — unless the user names them explicitly. In folders with recent files, move only files older than 14 days. (Pure caches and build outputs fall under rule 3 instead.)
2. **Regenerated by normal work = keep.** Things that come back on the next device build or sync (Xcode `iOS DeviceSupport`, Gradle caches, Playwright browsers, in-use simulator runtimes) are not worth deleting.
3. **Only pure caches and build outputs are deleted without asking** — and only when the owning app/tool is not running (`pgrep`). If it is running, ask the user to quit it, re-check, then delete.
4. **Everything else goes to the Trash** (`~/.Trash/cleanup-<date>/`), never `rm`. The user empties the Trash after checking. Trash is on the same disk, so report two numbers: free now, and free after emptying.
5. **Never fight macOS protection.** "Operation not permitted" under `sudo` = SIP/TCC-protected (e.g. `/Library/Developer/CoreSimulator/Caches`, `~/Library/Containers/<id>` roots, Photos/Mail/Messages). Inside an app container move only subfolders of `Data/`. Do not suggest `sudo rm`; skip it or point to the owning app / System Settings → Storage.
6. **Look inside before you delete orphaned app data.** Containers of uninstalled apps often hold the user's own videos/projects — move those to the drive first.
7. **App working folders are not media.** `~/Movies/CapCut`, `Luminar catalogs`, `*.photoslibrary`, `*.lrlibrary` look like media but are app data; moving them breaks the app. Treat as app data.
8. **Check the external drive's filesystem first.** NTFS is read-only on macOS → stop and tell the user. exFAT works but creates `._*` AppleDouble files and wastes space on small files.

## Workflow
1. **Scan (read-only).** Run `bash scripts/scan.sh` (≈2–5 min). Stamp `df -h` before. Note what `du` couldn't read.
2. **Classify** every finding into batches and show one table with sizes and last-use dates:
   - **A — delete now:** build outputs (`DerivedData`, `build/`, custom derived-data dirs), caches of stopped apps (`~/Library/Caches/<app>`), `npm cache clean --force`, `brew cleanup -s`.
   - **B — data of uninstalled / long-unused apps** (inspect contents first, rule 6).
   - **C — dev tooling** (simulators, emulators/AVDs, system images, SDK caches) — keep what rule 1/2 protects.
   - **D — app caches the user clears in-app** (Telegram, Chrome on-device model, Discord) — list as user actions.
   - **E — stale worktrees / `node_modules` / old toolchain versions** — check git status and dates.
   - **M — move to external drive:** media/archives untouched for > 6 months; recent-media folders only if the user says they're not in work; backups get a copy off the machine (keep the newest one locally via `copy:`). If M frees little, say so — the big wins are usually A–C.
   - **Ask separately:** Time Machine local snapshots (`tmutil deletelocalsnapshots`), only if the scan shows any.
   - **Keep:** browser profiles, active projects, anything rule 1 protects.
3. **Execute batch A**, re-measure with `df -h`.
4. **Ask once with batched multi-select questions** (one question per batch, options = sub-groups with size + last-use). The user's free-text answers often carry new rules — apply them to all later batches.
5. **Execute approved items:** deletions → Trash dir; for B, move user media to the drive first.
6. **Offload M:** write a list of `$HOME`-relative paths and run
   `zsh scripts/offload.sh --dest "/Volumes/<Drive>/$(scutil --get ComputerName)/Archive-<YYYY-MM>" --list paths.txt --dry-run`, then without `--dry-run`
   (copies, verifies with `rsync -c`, moves originals to the Trash; prefix a line with `copy:` to keep the original; files newer than 14 days stay in place). Keep `paths.txt` in the scratchpad. Run it in the background for large sets. Any `*-FAIL` line = original left in place; report it.
7. **Write the restore manifest:** `bash scripts/manifest.sh "<archive dir>"` → `RESTORE-MANIFEST.txt` with the path mapping, restore commands, summary and full file list.
8. **Report:** free space before/after, what went where, what's in the Trash, and the remaining **user actions** (empty Trash after checking the drive, in-app cache clears, closing apps whose caches are pending).

## Common mistakes
| Mistake | Instead |
|---|---|
| `rm -rf` originals after copying | Move to `~/.Trash/cleanup-<date>/`; user empties it |
| "Recommend deleting dyld cache / simulator" used yesterday | Rule 1: used within 14 days → keep |
| `sudo rm` on a protected path | Rule 5: skip, explain |
| Archiving `Movies/CapCut` as "videos" | Rule 7: app data, leave it |
| Deleting an orphaned editor container wholesale | Rule 6: find `*.mov/*.mp4` inside, move them first |
| Moving a whole screenshots folder that's still in use | Move only files older than 14 days |
| Manifest with checksums only | Manifest maps every file back to its original path with restore commands |
| Deleting Chrome/Android Studio caches while they run | Ask the user to quit, then delete |
| One question per item | One question per batch |
